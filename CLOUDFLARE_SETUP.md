# Публикация sat9

## Cloudflare Worker

Репозиторий — `saidkhujalucky-hub/sat9`. В исходной конфигурации Worker называется **sat8**; это имя сохранено, чтобы обновить тот же Worker и сохранить его данные. Если в Cloudflare используется другое имя, укажи его в `wrangler.toml`.

1. Подключи этот репозиторий к существующему Worker. Deploy command: `npm run deploy`; отдельная build command не требуется.
2. `npm ci` использует согласованный `package-lock.json`. Версии инструментов закреплены.
3. D1 привязан как `DB`, база `sat-platform-db`. Wrangler поддерживает автоматическое создание привязки. Если база уже существует и Cloudflare просит выбор/ID, укажи реальный `database_id` в блоке D1. Нельзя подставлять случайный ID или создавать новую базу вместо действующей.
4. Таблицы создаются при первом API-запросе. Проверка: `https://АДРЕС-WORKER/api/health` → `ok: true`, `database: d1`.
5. Открой сайт, зарегистрируй тестовый аккаунт, сохрани личный код в «Безопасности», начни тренировку. Проверь вход и продолжение с другого устройства, завершение четырёх модулей и историю.

Оплата оставлена в исходном режиме `manual`: этот выпуск не подключает новую кассу или карту.

## Машинный перевод

В `wrangler.toml` добавлена привязка Workers AI `AI`. В аккаунте Cloudflare должна быть доступна служба Workers AI. Модель `@cf/meta/m2m100-1.2b` переводит по запросу пользователя; результат кэшируется в D1. Действуют лимиты и тарифы твоего аккаунта Cloudflare. Этот выпуск сам не меняет тариф аккаунта.

Кнопка перевода доступна в тренировке, похожих заданиях и разборе законченного теста. В активном экзамене сервер возвращает 403. Исходный английский текст и рисунки сохраняются. При недоступном сервисе показывается сообщение, исходный текст остаётся доступен.

## Письма для аккаунтов

В Cloudflare → Worker → Settings → Variables and Secrets:

- `RESEND_API_KEY` — **Secret**, ключ сервиса Resend.
- `MAIL_FROM` — подтверждённый в Resend адрес отправителя.
- `FRONTEND_URL` — полный HTTPS-адрес главной папки сайта с `/` в конце.

После изменения настроек выполни повторный deploy. Письма отправляются по запросу пользователя. Ссылки живут 30 минут и используются один раз. Без этих настроек восстановление по сохранённому личному коду работает; отправка писем скрыта. Пароли и ключи не размещай в GitHub или `public/`.

## GitHub Pages, если используется отдельно

Worker уже раздаёт весь сайт и API на одном домене. Дополнительная публикация в Pages необязательна.

Для Pages: Settings → Pages → GitHub Actions; Actions variable `API_URL` = полный адрес Worker с `/api` в конце. Workflow Pages запускается только при заданном `API_URL`. Сборка без правильного HTTPS-адреса останавливается вместо публикации неработающего API.

Если ограничиваешь CORS, перечисли в `ALLOWED_ORIGINS` разрешённые origin через запятую, без пути репозитория. Для писем `FRONTEND_URL` должен указывать именно на используемый пользователями сайт.

## Ограничения проверки

Локальные тесты не подтверждают права и настройки твоего аккаунта Cloudflare, доставку реальных писем или доступность внешнего банка всех вопросов из опубликованного Worker. Эти проверки выполняются после деплоя на фактическом домене.
